## X-ICP ternary localizability gate — VALIDATED, recommend ON @ fullRatio 0.05

n=24 A/B, near-IR substrate, governor OFF, paired on one freshly-built binary:

| leg | DIV | bounded (SLOSH/SLOSH_HI) | worst max\|x\| | deg max |
| --- | --- | --- | --- | --- |
| base (xicp off) | **7/24** | 16 | 11,912 m | **6** |
| xicp ternary 0.05 | **0/23 clean** (1 crash, below) | 23 | 212 m | **1** |

Fisher one-sided p = **0.0055** (crash-excluded) / 0.024 (crash counted). The
partial-admit band across `[degeneracyThreshRatio, fullRatio] * lambda_max` replaces
the binary gate's on/off toggle on marginal directions; that toggle's scan-to-scan
chatter is what *seeds* the runaway. With the band, **degeneracy never exceeds 1
direction** across all 23 reps — the gate **prevents** the deg=6 collapse rather than
bounding it after the fact (contrast the governor, `1f19632`, which bounds the
held-prior runaway). `fullRatio=0.05` beat `0.02` (tighter worst-case, no deg=6
excursion); the params.yaml default 0.05 is the validated value. A clean re-run
(n=3, free cores) was 3/3 bounded, 0 crashes.

## GenZ-ICP adaptive blend — NEGATIVE on this bag

pointWeight {1, 10, 100} (floor 0.5, knee 0.1) never prevented the deg=6 collapse;
pw=100 was *catastrophic* (4/5 DIV — the isotropic point-to-point mass over-
regularizes and corrupts the plane constraints). The isotropic term dilutes off the
unobservable axis, same failure mode as the auxiliary observation terms. Leave
`odom/genz/enabled` default-off; documented as tested-negative, not removed.

## OPEN — latent crash in the photometric residual loop (not from this cycle's code)

1 of 48 A/B reps crashed: `std::out_of_range` /
`vector::_M_range_check: __n (327563643) >= size (4763530)`. The only range-checked
`.at()` in the tree is `src/nano_gicp/nano_gicp.cc:1503` (`src.at(i)` in the
OMP-parallel photometric loop — the lidar_image term), which runs every scan on both
A/B legs and which neither GenZ nor X-ICP touch. The control leg ran it 24x clean;
the crashed rep was the most CPU-loaded (43.7 ms vs ~10 ms) and in deg=6 divergence.
Garbage index ⇒ a **load-triggered data race / use-after-free on the source cloud**
(the threading-hazard class flagged in the repo guidance), pre-existing and exposed
under contention. Candidate hardening: audit the cloud lifetime around the parallel
photometric loop, and guard against non-finite projected (u, v) — NaN bypasses the
`u < bw || u > umax` bounds checks because NaN compares false. Tracked as a follow-up.

## PM addendum — reproduction caveat + governor interaction

Re-ran on a fresh `--no-cache` image + clean container (deps re-pulled; the basin is
stack-sensitive) to reproduce X-ICP-alone and test X-ICP + governor.

- **Reproduction caveat.** X-ICP-alone (fullRatio 0.05) re-ran at **2/24 DIV** (worst
  49.9 km; both DIVs early), NOT the lucky 0/23 above. Still robustly beats base 7/24 —
  effect real and large — but the headline "zero" was optimistic; treat the rate as
  ~2/24 (~8%). Chaotic-basin reproduction lesson: don't read a single n=24 as exact.
- **X-ICP + governor do NOT compose cleanly.** Combo run (incomplete at 11/24 when the
  host was shut down: 1 DIV @ 14 km that the governor did NOT bound, 1 SLOSH_HI @ 371 m).
  Mechanism (gate loop `src/nano_gicp/nano_gicp.cc:1132-1160`): the governor records a
  held axis for clamping only when `lam <= tt_thresh` (hard-degenerate, 0.005*lmax);
  X-ICP's **partial-admit band** `tt_thresh < lam < tt_full` (0.005-0.05*lmax) takes a
  partial data update but is **not** recorded for the governor — so a runaway proceeding
  along a partially-admitted axis escapes the clamp. They cover disjoint axis sets.
  **Follow-up to make it a true belt-and-suspenders:** also record the partial-band
  directions for the governor (clamp them proportionally to 1-keep). Re-run the combo
  n=24 to confirm. Harness data: resple_test_ws `results/dliio_nrun/combo_2026-06-25/`.
