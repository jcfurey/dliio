## n=24 Finding 1 — X-ICP-alone is stack-fragile (NOT a 0cac829 regression)

`xibase` (X-ICP ternary fullRatio 0.05, governor off, verified `ternaryEnabled: true`
in the merged config): **8/24 genuine deg=6 DIV** (worst 31.7 km, 0 crashes) — ~the
*bare-baseline* (X-ICP-OFF) rate of 2026-06-25 (7/24), not the validated X-ICP-ON
rate. X-ICP-alone DIV across three successive fresh builds is now **0/23 → 2/24 → 8/24**.

Ruled out a `0cac829` regression by reading the diff: the X-ICP change is purely
additive — the gate update `dx.head<3>() -= v*comp*(1-keep)` is byte-identical; the
commit only adds `last_degen_{rot,trans}_dirs_.push_back(v)`, which is read *only by
the governor* and is inert when the governor is off (as in `xibase`). So `xibase` is
bit-identical to the pre-`0cac829` X-ICP path.

**Conclusion:** the basin is more recompile-sensitive than the single p=0.0055
validation implied — adding four default-off features shifts binary layout → FP
rounding → trajectory, moving the basin. **X-ICP-alone is not a robust standalone
fix**; a deployable recommendation must add a hard bounding mechanism (governor or
observer slice). This strengthens, rather than overturns, the 2026-06-25 PM
reproduction caveat.

**Verdict — nothing cleanly deployable yet; the crash is the single blocker.**

- **The governor is the only decisive divergence-prevention.** `combo` drives genuine
  DIV to **0/24** (crash-excluded 0/18 vs 8/24, **p=0.0062**, mirroring the 2026-06-25
  X-ICP p=0.0055). The `0cac829` partial-band compose-fix works — no governor escapes,
  everything bounded ≤185 m; the 14 km combo escape of 2026-06-25 is gone. **But the
  6/24 crash erases the benefit at the deployment level:** total failures (DIV+crash)
  6/24 vs baseline 8/24 is NOT significant (p=0.38).
- **The observer slice (slice05) doesn't crash but only halves DIV** — 4/24 vs 8/24,
  not significant (p=0.16). degenObsGain 0.5 is insufficient *alone*; it is the
  crash-free fallback. (Its first 5 reps were 5/5 bounded — a low-n streak; the basin's
  DIVs clustered later. Do not read low-n as the rate.)
- **Fix the crash → `combo` (0/24 genuine DIV) is the deployable winner.**

## n=24 Finding 2 — the 0cac829 crash fix is INSUFFICIENT; combo crashes 6/24

`combo` (X-ICP + governor 0.15) crashed **6/24** with the *same* signature `0cac829`
item #3 claimed to fix:
`std::out_of_range / vector::_M_range_check: __n (74285787) >= size (3495924)`, firing
immediately after `degenerate along 6 direction(s)` warnings (deg=6 divergence, high
load). The rate (6/24 ≈ 25%) is far above the original 1/48.

- **Combo's *algorithm* is fine; the raw *metrics* are crash-contaminated.** The 18
  non-crashed reps are all bounded (0 genuine DIV, ≤185 m). Each crashed rep's raw
  verdict reads DIV — an artifact: the node dies mid-bag (truncated ~14–16k poses vs
  ~19,880), the unguided IMU integrates into runaway, and the stub scores as DIV.
  Combo does not *diverge*; it *crashes* — more deployment-fatal.
- **Crash localizes to the governor path** (p=0.011). `xibase` and `slice05` (gov off):
  0/24 crashes each, despite reaching deg=6. `combo` (gov on): 6/24. The governor keeps
  the node alive and processing *longer* in the deg=6 contended state (vs `xibase`
  diverging freely), widening the photometric-loop race window — or its extra per-scan
  work (clamp + cov inflation + the new partial-band dir recording) shifts timing into
  the race.
- The garbage index `74285787 ≫ size 3495924` is a corrupt *loop/computed index* (or
  heap corruption), not merely a freed cloud — so `0cac829`'s `src_ptr` ownership in
  `accumulateVisualResidual` addressed only one vector and missed the real one.
